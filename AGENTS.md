# AGENTS.md

Guidance for AI coding agents (and humans) working in this repository.

## Project Overview

Hansa is a Crystal shard that detects the programming language of
source code based on content only — no filename, no extension. It is
a port of the naive Bayes classifier from
[go-enry](https://github.com/go-enry/go-enry), trained on the Linguist
corpus.

Known classifier quirks, documented as specs rather than bugs:

- Crystal code is usually detected as Ruby (its closest corpus relative).
- Go is sometimes detected as Golo.
- Short files can be detected as almost anything.

## Commands

- `shards install` — install dependencies
- `shards build` — build the `hansa` CLI into `bin/hansa`
- `crystal spec` — run the test suite
- `ameba` / `ameba --fix` — lint / auto-fix; must be clean before a
  task is declared finished
- `shards version` — show the current version

## Architecture

- `src/hansa.cr` — the whole library:
  - `BakedData` embeds `src/data/frequencies.json` (the training
    tables, ~7.9MB of JSON) into the binary at compile time. It is
    gzipped at bake time and decompressed transparently on read.
  - `Classifier` tokenizes the first 50K characters (shebang, SGML
    tags, punctuation, operators, identifiers; comments and string
    and number literals are stripped) and scores the tokens with
    naive Bayes over the 100 most common corpus languages.
  - `Hansa.classifier` exposes the lazily parsed `Classifier`; the
    JSON is parsed on first use, not at require time.
  - `Hansa.classify(code)` returns the top-scoring language name.
- `src/main.cr` — CLI entry point: `exit Hansa::CLI.run(ARGV)`.
- `src/cli.cr` — the CLI itself (docopt-based): usage/help/version,
  classifies each file argument, `-` reads standard input, errors go
  to stderr with a non-zero exit code. Only reads the first 256KB of
  each file since the classifier caps at 50K characters. `run` takes
  injectable IOs so it is spec-tested directly.
- `src/data/frequencies.json` — language/token log-probabilities. To
  regenerate it, check out go-enry next to this repo and run
  `python scripts/extract_constants.py` from the repo root.
- `spec/hansa_spec.cr` — expected values were verified against the
  classifier output; when behavior intentionally changes, update the
  specs to document the new expectation.

## Workflow Rules

- Never modify anything under `lib/` — external dependencies.
- Build before declaring a task done; if a project has more than one
  binary, build all of them.
- Run `crystal spec` and `ameba` before declaring a task finished.
- Don't commit binaries or build artifacts (`bin/` and `lib/` are
  gitignored).
- No `not_nil!`, and don't use `to_s` to paper over nilable values.

## Releases

- Use conventional commit messages (`fix:`, `feat:`, `perf:`, `docs:`,
  `chore:`) — the changelog is generated with
  [git-cliff](https://git-cliff.com).
- `CHANGELOG.md` is generated by `git cliff -o CHANGELOG.md`; don't
  hand-edit it.
- The version lives in `shard.yml`. To release: bump it, commit, tag
  `vX.Y.Z`, regenerate the changelog, commit, push, and create the
  GitHub release with `gh release create`.
